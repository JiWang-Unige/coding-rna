## 1. 现有语法里内含子是怎么处理的

训练损失（`a1_dp` → `full_grammar_coarse_channel` → `full_grammar_boundary_compiled`）和解码（`m29_skyline_reuse`）都跑在同一个逐碱基有限状态自动机上，状态 = (阶段, 已用外显子数, 实际未完成密码子)，cap 128 时共 19,078 个状态。内含子依次经过 D0 → D1 → I2 → I3 → AG：GT/GC 两个碱基、一个必经碱基、I3 自环 k 次、AG 两个碱基，所以长度 n = 5 + k，最短 5 bp。

I3 自环上只有该碱基的内含子角色分数（logit 减背景 logit），没有单独的长度项。整个内含子的长度分布因此由编码器逐碱基给出，语法本身只隐含一个几何分布，而且这个几何分布的速率会被头部的偏置吸收。

## 2. 设计

### 2.1 状态

把 I3 拆成两条分支，两条分支都从 I2 进入、都经由原来的 AG 离开：
- **短分支** I3S1…I3Sr（r = `short_stages`），
- **长分支** I3L。

每个分支各带 (外显子数, 实际未完成密码子)，所以自然就是"每个相位、每段历史各有一对长短状态"。其余阶段、角色、剪接位点、5 bp 最短内含子、外显子上限都调用冻结的 `_transitions`，没有改动。

每条边带一个类型，边的分数 = 角色分数 + bonus[类型]：

| 类型 | 边 | bonus |
|---|---|---|
| 1 / 2 | I2 → I3S1 / I3L | log π_S / log(1−π_S) |
| 3 | 短分支自环 | log p_S − log p0 |
| 4 | 短分支前进（只在 r > 1 时有） | log(1−p_S) − log p0 |
| 5 | I3Sr → AG | log(1−p_S) − log(1−p0) |
| 6 / 7 | 长分支自环 / I3L → AG | log p_L − log p0 / log(1−p_L) − log(1−p0) |

可学习的参数只有三个标量 θ = (a, b_S, b_L)：π_S = σ(a)，p_S = σ(b_S)，p_L = σ(b_L)；三个相位共用。p0 是单一几何分布的最大似然估计，固定不变。

### 2.2 长度分布与"形状规范"

对路径求和后，每个内含子得到的长度项是 log P(k) − log Geom(k; p0)，其中 P(k) = π_S·NB(k−(r−1); r, p_S) + (1−π_S)·Geom(k; p_L)。r = 1 时就是两个几何分布的混合。

我们只加入"不是几何分布的那部分"：常数项和每碱基线性项本来就能被头部的内含子偏置和供体偏置吸收。这样做，起点和 T2 基本相同。若直接加 log P(k)（"绝对规范"），每个内含子一上来要扣约 5 nat。

初值来自训练染色体（拟南芥 NC_003070.9 / NC_003076.8，水稻 NC_089043.1 / NC_089046.1）上合格转录本的内含子（68,435 个）的最大似然拟合。提取脚本是 `m41_intron_lengths.py`，拟合脚本是 `m41_prior.py fit`，结果在 `results/intron_prior_fit.json`。不用 DEV，也不用验证染色体。

| 模型 | BIC | π_S | 短分支均值 | 长分支均值 |
|---|---|---|---|---|
| 单几何（相当于现状） | 864,997 | – | 209 bp | – |
| r = 1（两个几何的混合） | 853,122 | 0.952 | 160 bp | 1,174 bp |
| r = 2 | 827,300 | 0.873 | 134 bp | 723 bp |
| r = 4 | 808,401 | 0.779 | 113 bp | 545 bp |

r 越大，越能拟合植物内含子在 80–100 bp 处的尖峰（1% 分位数 67–70 bp）。但 r > 1 时解码会出问题，见 2.4。

### 2.3 配分函数与梯度

稠密 FP64 前向–反向（算法与 `full_grammar_boundary_compiled` 加 M29 alpha arena 相同），只多一样东西：对 bonus 向量的梯度。θ 的梯度再经 `m41_prior.bonus` 用 autograd 链式求出。

隐分支（长或短）在 logZ 里求和，所以训练的就是 2.2 的混合长度分布。观测部分（精确角色行、ε = 0.1 的粗通道、未知行）不变：两条分支都发内含子角色 4–6，观测掩码对它们一视同仁。

### 2.4 精确解码

解码沿用 M29 skyline，只在边分数上加 bonus。它求的是"基因结构 + 隐分支路径"的联合最大值，和 Tiberius / Vipsania 的 HMM Viterbi 语义一致。同 (阶段, 未完成密码子)、外显子数更少的状态支配更多的状态，这条剪枝在新阶段上仍然成立。

联合最大值与"只对结构取最大"之间的差：
- r = 1 时每个内含子最多差 log 2（两条分支各只有一条路径）；
- r > 1 时短分支长度为 k 的路径有 C(k, r−1) 条，求和时有这个组合数，取最大时没有。所以解码看到的短分支只是一条较陡的几何分布，看不到众数。

干跑（§6）证实了这一点：r = 4 时解码一次都没走短分支，≥6 段的 F1 从 76.0 掉到 61.1。要在 r > 1 时做到训练–解码一致，需要按长度展开确定性状态链，每多一个状态就多 2,667 个自动机状态（50 bp 的下限约需 13 万个状态）。因此预注册 **r = 1**。

### 2.5 复杂度与显存

| | 冻结 | r = 1 | r = 4 |
|---|---|---|---|
| 自动机状态（cap 128） | 19,078 | 21,745（+14%） | 29,746（+56%） |
| 单窗口 DP（49 kb，CPU，本机两次） | 4.1–5.5 s | 6.2–6.7 s（×1.2–1.5） | – |
| 4 Mb 解码检查点 | 71 MB | 81 MB | 111 MB |
| 4 Mb skyline 解码时间（ont，单核） | 14–16 s | 16 s | 36 s |

DP 和解码都在 CPU 上，GPU 显存不变（编码器、LoRA、头都不动）。T2 训练每步约 26 s，其中 8 个窗口的 DP 合计约 50 s，由 12 个进程并行、与 GPU 前向重叠。所以每步预计慢 0–15%。

## 3. 对照臂 T2_ILS

除下面列出的两点外，与 T2（M34 pc2，seed 0 / sampling seed 1）完全相同：同一个 draw schedule 文件 `schedule_T2.jsonl`（即配对的同一批抽样），同一初始化（M32 冻结头），同一 LoRA，同一套 LR / 步数（3,072 步 cosine）/ 批大小 8 / ε / 外显子上限 / 检查点间隔，同一选点规则（在 {1536, 2304, 3072} 中取 Ath NC_003071.7 + Osa NC_089044.1 合并 F1 最大者，平局取大步数）。

只有两处不同：
1. 语法：r = 1 的长短内含子状态（`m41_grammar`），训练和所有解码（验证、DEV、B 集）都用它；
2. θ 从 2.2 的拟合值起步，用自己的 AdamW 训练：峰值 LR 1e-3，末值 1e-4，与头部相同的 warmup 和 betas，weight decay 0。梯度权重与头部相同（1 / n_known / batch），单独裁剪到范数 1。头部和 LoRA 的裁剪不受影响。

入口 `m41_stage.sh`，输出 `outputs/M41-INTRON-LENGTH/pc2_T2_ILS/`，trainer 是 `m41_train.py`（M34 主循环，新增行标 [M41]），推理是 `m41_infer.py`（导入 `m34_infer` / `m34_p2b_infer`，只把解码器换成 M41 的），评分用的都是 M34 / M32 的原脚本。

### 4.2 主要指标与判据（写在任何结果之前）

主要指标：DEV ≥6 段层的精确链 F1。T2 为 71.69，Carbon-A 过滤为 76.49，差距 4.80。
次要指标：DEV 整体精确链 F1（T2 73.88）、B 集合并 F1（T2 68.47）。

噪声标尺取 T2 三个 seed 之间的离散度（seed 0 / s2 / s3）：

| | seed 0 | s2 | s3 | 均值 ± SD |
|---|---|---|---|---|
| DEV 整体 | 73.88 | 74.09 | 71.65 | 73.21 ± 1.35 |
| DEV ≥6 段 | 71.69 | 71.36 | 69.30 | 70.78 ± 1.29 |
| B 集合并 | 68.47 | 66.86 | 65.93 | 67.09 ± 1.29 |

为什么不用 bootstrap 区间做判据：块 bootstrap 只反映评估集的抽样误差，反映不了训练的随机性。例如 T2_s2 − T2 在 B 集上是 −1.61，配对区间 [−1.96, −1.28] 不含 0，但这只是两个 seed 之间的差。所以门槛按 seed SD 定，bootstrap 区间只作必要条件。另外，seed 0 在三项上都是最好或接近最好的 seed，与它配对比较是偏保守的。

设 d(≥6)、d(整体)、d(B) 分别为 T2_ILS 减 T2（seed 0）的点差：

- **支持**：d(≥6) ≥ +2.58（2 × 1.29），且 ≥6 层配对区间下限 > 0，且 d(整体) > −1.35，且 d(B) > −2.58。
- **有害**：d(≥6) ≤ −2.58，或 d(整体) ≤ −2.70。
- **灰区**：+1.29 ≤ d(≥6) < +2.58 且区间下限 > 0；或者满足"支持"的 ≥6 段条件，但 d(整体) ≤ −1.35；或者 DEV 满足"支持"但 d(B) ≤ −2.58（只在 DEV 上有效）。
- **无可检测效果**：其余情况。

只跑一个 seed，只能检出约 2.6 个点以上的效果。落在灰区时，可以再加 T2_ILS_s2 / s3 两个 seed（用 T2_s2 / T2_s3 的 schedule 与 lora_seed，约 2 × 32 GPU h），再与 T2 的三个 seed 比均值；这一步要用户另行决定，不自动排队。

无论结论如何，都不改终版模型 T2，也不改已冻结的结果（C1 面板、k 臂）。若结论为"支持"，是否改换终版模型由用户另议。
