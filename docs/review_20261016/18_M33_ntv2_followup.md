## 1. 做法

### 1.1 推理（GPU，M32_DONE 出现且无 M32 进程后启动）
- 模型：`outputs/M31*/runB/model_001536.pt` 的拷贝（md5 4a89a856…，与原文件一致；拷贝是为了不让命令行出现 M31 目录名，M32 的队列驱动按该字符串判断 M31 进程）。
- 代码 `m33_infer.py`：M31 `c1_infer.py` 的拷贝，仅改三处——注册 M30 contig（含解码 worker）、**保留 15 角色势 `pot/*.npy`**（M31 推理后删除）、GFF id 前缀。编码窗口 12,288/步长 6,144、最近中心归属、整 contig 精确 skyline 解码，与 M31 完全一致。
- **复现校验**（`m33_repro_check.py`）：内部验证重新推理得 63.258，DEV 得 63.607，与 M31 原结果的**链集合逐条相同**（3,815/1,401 与 4,971/2,032 条全部相同）。
- 耗时（GPU 近乎独占，4 个解码 worker）：内部验证 843 s、DEV 1,318 s、Dryas B 2,278 s、Esch B 3,799 s；吞吐 162–207 kbp/s（双链计），峰值显存 2.24 GB；无中断、无报错。

### 1.2 后验（CPU）
- 能量 E_τ = τ·pot（B 无外部 offset；τ=1 即训练的 CRF 能量）。后验 = 冻结 `complete_gene_set_posteriors` + scaled-mass 查询（与 M29-A2/M30 同），对解码得到的**全部**链算 log P(g 在基因集中)；评分用项目 ruler（M26 CDS-assessable 主参考，精确 CDS 链，CDS≥96 规则）。命中 = 精确等于主参考链。ECE = 10 个等宽箱（`m29_r3_posterior_filter.reliability`）；AUROC/AP 用 R3 同一函数。
- `m33_posterior.py`（M30 `m30_posterior.py` 的变体）+ `m33_post_queue.py`（按大小排序的进程池，最多 8 个进程，避开 CPU 0/1）。合成数据测试（`tests/test_posterior_synth.py`）：'+'/'−' 链的方向往返一致、概率 ≤1、与直接调用一致。
- 评分器对 M30 四个对照臂的重算与 M30 报告逐位一致（73.98 / 72.32 / 71.97 / 74.09；73.32 / 71.75 / 71.38 / 72.52，`tests/repro_m30_arms.py`）。注意：本报告的 B 集 bootstrap 区间与 M30 报告在第二位小数略有差异（例如 Carbon-A 未过滤 Dryas [71.42, 73.19] 对 [71.47, 73.21]），原因是孤儿 100 kb 箱的集合随参与 bootstrap 的臂不同而变；点估计相同。

## 5. 解读

1. **后验校准与过滤的结论（步骤 1）**：对配分函数训练的 B，自家后验在 τ=1 校准（ECE 0.031，DEV 复现 0.031），不需要温度缩放；过滤带来 +1.7（DEV）与 +1.4（内部验证）的 F1，量级与 M29 R3（自家后验 +1.7）、M30（闸门+后验 +1.2–2.1）一致，且两个物种同向。它不能改变 B 与 Carbon-A（77.4）、GENERanno（70.1）之间的差距。
2. **泛化（步骤 2、3）**：同物种留出（TRAIN 64.7、内部验证 63.3、DEV 63.6）没有差距，但新物种上下降 13–20 点，而 Carbon-A 只下降 3–4 点。结论：**这个 pilot 配方没有给出"自监督骨干 + 框架 → 新物种"的零样本泛化**；时间留出面板才暴露了同物种面板看不出的问题（M31 §9 已预言 DEV 是同物种开发面板）。
3. **原因（未分离，只列可检验假说）**：(a) 头 + LoRA 在仅 2 个物种的约 4 条染色体上训练，学到的剪接位点/基因结构信号带有拟南芥/水稻特异性（拟南芥/水稻在结构上与 Dryas 蔷薇科、Eschscholzia 罂粟科相距较远）——可由增加训练物种数检验；(b) NT-v2 预训练不含植物，LoRA 只能补偿部分；Carbon-A/GENERanno 骨干有注释监督，且训练快照含大量植物；(c) 6-mer token 分辨率对精确连接的限制（M31 §7 已提）。本实验没有消融，不能在 (a)(b)(c) 之间归因。
4. 与 M30 的联系：M30 显示"同一后验过滤 + 固定阈值"可以让闸门追平 Carbon-A 过滤；本实验显示对 B 同样的过滤机制增益稳定（+2.3 到 +2.5），但这是在 B 的基线已经落后 20+ 点的基础上，不能解读为"追平"。

## 6. 局限与偏离
- 单 seed、单次划分、两个新物种；B 单模型（M31 无多 seed）；DEV 自助区间是 1 Mb 块，新物种是基因单位，二者不可直接比较宽度。
- τ 与阈值的选择依赖内部验证两条染色体（5,216 条解码链，5,894 参考），该区段也是 M31 选 checkpoint 的区段；内部验证过滤后 F1 64.67、DEV 65.29（DEV 反而更高），所以没有看到选择带来的乐观偏倚，但两条染色体的样本量有限。
- DEV 后验只算了 τ=1（即 τ\* 与协议中的"未校准 τ=1 对照"重合，所以 DEV 上没有独立的"校准前"行；τ 曲线只在内部验证上有）。
- 新物种参考是 RefSeq 计算注释，不是实验真值；B 的评估集参考只在最终评分里读取，没有用于选择。
- 描述性附加（预声明之外）：`m33_diag.py` 的失败形态分解、"事后最优阈值 F1"，均不用于任何选择，已标注。
- 同源/训练泄漏审计未做（沿用 M30 的限定）：Carbon-A 的训练快照是否含 Dryas/Eschscholzia 近缘序列未知，这只会让 Carbon-A 的数字偏乐观，不影响 B 的结论。
- 过程记录：等待器曾因本机网络中断（ENOTIFOUND）一次误报"M32 进程消失"；核对后 M32 仍在运行，没有启动任何 GPU 任务，随后加了探测为空不当作证据的保护。M32 在 2026-10-21 约 11:44 完成其训练阶段并写出 M32_DONE 之后我才启动 GPU 任务，所有 M33 任务无中断。
