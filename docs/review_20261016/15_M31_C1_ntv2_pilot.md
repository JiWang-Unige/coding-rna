## 1. 适配层设计

### 1.1 NT-v2 与窗口

NT-v2-500M：29 层、隐藏维 1024、RoPE、非重叠 6-mer 词表（4,107）、最大 2,048 个内容 token + CLS，即 12,288 bp。历史 M9–M23 用的是 2,046 bp 窗口（341 token）和解冻顶部 12 层（"L12" 指解冻层数，不是取第 12 层特征），特征取最后一层（`last_hidden_state`）。本次首次用满 12 kb 上下文。

| 项 | GENERanno（M28） | NT-v2（本实验） |
|---|---|---|
| 窗口 / 步长 | 24,576 / 12,288 bp | **12,288 / 6,144 bp**（同样 50% 重叠） |
| token 数 | 4,096 | 2,048 |
| 特征维 | 2,048 | 1,024 × 层数（本实验 2 层拼接 = 2,048） |
| 重叠拼接 | 最近窗口中心拥有（`context_segments`，平局取较小起点） | 同一冻结函数，同一规则 |
| token→碱基 | `SharedContext`：每 token 特征经线性+BiGRU 后 `repeat_interleave(6)`，再与 DNA one-hot 卷积分支融合 | **完全复用**（NT-v2 同为非重叠 6-mer，对齐关系相同，无需新的上采样模块） |

要点：
- **手工构造 token**：官方分词器遇到含 N 的 6-mer 会拆成单字符，破坏"1 token = 6 bp"对齐。本实现对每个 6-mer 块查词表，含非 ACGT 的块用单字符 `N` 的 id；窗口右端补 N 到 12,288（与 M28 的"定向后右补 N"一致）；前置 CLS、输出丢弃 CLS。
- **注意力**：远程代码是 eager 注意力且 rotary 表为 FP32，纯 BF16 模型会 dtype 冲突。采用 FP32 权重 + BF16 autocast（同历史 M9 的 AMP 做法），并把注意力替换为等价的融合 SDPA（rotary 仍 FP32；与 eager 路径逐 token 余弦 0.9999，相对误差约 1%，BF16 量级）。吞吐 0.087 s/窗（共享 GPU）。
- **头**：`M28Core('C0', 2048, 128)`（C0 结构不变；输入维 2,048 来自两层拼接，参数量仍为 366,191，与 M28 一致）。训练目标、15 角色、完整语法、skyline 解码器、ruler 全部直接复用，没有新增语法代码。

### 1.2 选层：历史最佳层 vs 层探针（偏离说明）

任务要求先用历史最佳层。历史最佳是"解冻顶部 12 层、取最后一层"，而冻结时历史 L0 对照仅 gbF1 0.8284（解冻后 0.9035）——说明冻结的最后一层特征本身偏弱。本次编码器是冻结的，所以先做了一个廉价的层探针（`layer_probe.py`，约 3 分钟）：对 hidden_states 0..29 各训练一个线性探针（每层先做无参数 LayerNorm），目标是每个 6-mer token 的三分类区域标签（背景/CDS/内含子，取 token 中心碱基；4 条训练染色体 80 个窗口训练，2 条内部验证染色体 80 个窗口评估，323,859 个 token；不含 DEV）。

| hidden_state | 29（历史：最后一层） | 28 | 27 | 26 | 23 | 21 | 18 | 12 | 8 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| macro-F1 | 0.771 | 0.805 | **0.816** | 0.812 | 0.811 | 0.811 | 0.809 | 0.784 | 0.778 |

最后一层比中间层（≈18–27）低约 4 个 macro-F1 点（CDS 类 0.79 对 0.87，内含子 0.56 对 0.61），中间层之间差异在噪声内。**预先设定的规则**："若最后一层与最优层相差 ≤1 点则用历史层，否则取排名最前的两层拼接"。结果相差 4.5 点，所以特征 = hidden_states **21 与 27 拼接**（各自无参数 LayerNorm），保持 2,048 维。这是对"先用历史最佳层"的偏离，已在此记录；注意：全管线里没有用"最后一层"重跑对照，所以层的贡献与其他设计（窗口、冻结）混在一起，不能单独归因。

### 1.3 训练窗口与几何

训练样本沿用 M28/M29 的 fresh-joint 抽样（seed 1，层内均匀有放回，保留原层序）：24,576 bp 核心 + 两侧各一个 12,288 bp 邻居 = 最长 49,152 bp 的 DP 上下文，核心内有精细/粗区域标签，其余位置未知（边缘化）。为保持 DP、标签和归一化与 M28 完全一致，上下文几何不变，只是用 12,288/6,144 的 NT 窗口网格（最长 7 个窗口）编码并按最近中心拥有。

测试（ont，全部通过）：
- `test_c1_geometry.py`（9 项）：token 对齐、窗口网格覆盖与"最近中心拥有"（对暴力定义）、**训练路径 `owned_context_logits` == 推理路径 `stitch_contig_emissions`**（正负链，逐位相等）。
- `test_c1_dp_parallel.py`：并行 DP（进程池 + 共享分配器）与冻结串行实现在 4 个真实 TRAIN 窗口（NT 规模上下文、随机 logits）上**损失与梯度逐位相同**，且拟南芥/水稻各链都含基因；采样器断言留出染色体永不被抽到。
- `test_c1_head_batch.py`：批量头调用与逐窗口调用一致（含短窗、含 N）。
- `test_lora_equiv.py`：逐块前向与 HF 路径一致；LoRA 零初始化为恒等；LoRA 状态存取往返一致；梯度只到 LoRA 参数。

### 1.4 内部验证与 checkpoint 选择

按 M29-A2 的做法，**留出拟南芥 NC_003071.7（19.7 Mb，4,293 条参考）与水稻 NC_089044.1（23.9 Mb，1,601 条）**：训练采样不使用（该层按同物种同链向的训练染色体层替代，保持计划结构）。内部验证 = 在这两条完整染色体上推理，用项目 ruler 算 pooled exact-chain F1（5,894 条参考），每 512 步一次；早停 patience 2。训练实际用的是 4 条染色体（拟南芥 NC_003070.9、NC_003076.8，水稻 NC_089043.1、NC_089046.1）。

## 3. 训练 A：冻结编码器 + 头

## 4. 训练 B：A 的头 + LoRA

触发条件（预先写明）：A 的内部验证明显欠拟合。证据：A 的 TRAIN/内部验证/DEV 三者几乎相等（§5），瓶颈在冻结特征。

配方：从 A step 2048 的头继续；在 NT-v2 第 13–27 块（0 起 12–26，共 15 块；特征 hidden_states 21、27 不经过第 28–29 块，故这两块不运行）的 query/value 加 rank-8 LoRA（alpha 16，491,520 参数，FP32）；同一 fresh 抽样序列（接在 A 已用的 2048×8 个抽样之后）；头 lr 峰值 1e-4、LoRA lr 峰值 3e-4（M28 的 rank-4 q/v 原生 lr 结论），均 cosine 到 1e-5；batch 8、1,536 步；每 512 步内部验证。编码器随 LoRA 改变，故无法预取特征：每个样本先 no-grad 前向得到 DP 输入，DP 并行完成后分块（2 窗）重算并反传（类 gradient checkpoint）。

## 7. 瓶颈分析与决策门

**决策门**（预设：≥60 成立；40–60 部分成立；<40 不成立）。最终选定模型 B：DEV **63.61 ⇒ C1 方向成立**。冻结编码器单独（A）为 50.92 ⇒ "部分成立"；因此结论是：**需要 LoRA 级别的编码器适配，纯冻结特征不够**。

瓶颈（按证据强度）：
1. **冻结特征的容量**（强）：A 的 TRAIN≈验证≈DEV（51.7/50.1/50.9），训练 NLL 已到千分位而 F1 停在 50；LoRA（49 万参数）一步带来 DEV +12.7。B 同样无泛化差距（64.7/63.3/63.6），且验证曲线在 lr 退火后仍升 1.5 点，说明尚未饱和。
2. **连接精度而非基因覆盖**（强）：B 的 CDS 碱基 F1 93.2（GENERanno 94.9），但 ≥6 段链 F1 53.98 对 65.81、2–5 段 63.71 对 67.75、单段 75.71 对 79.85。差距随外显子数增大，与 M29-R4 对 Carbon-A 的结论一致（差距在剪接连接）。6-mer token 分辨率 + 冻结表示对精确剪接位点不够，LoRA 有明显帮助。
3. **水稻弱于拟南芥**（中）：B 水稻 56.35 对拟南芥 66.62（GENERanno 63.73/72.86），差距比例相近（水稻基因结构更复杂，且训练只用了水稻 2 条染色体、约 3,300 条参考）。
4. **训练量**（中）：只用 4 条训练染色体、B 仅 1,536 步；M28 的经验也是容量/数据是瓶颈（1,491 个窗口只占 6%）。
5. **上下文/分辨率/选层**（未能分离）：窗口 12 kb 对 GENERanno 的 24 kb、层选择（21+27，层探针依据）都与骨干本身混杂，没有做单因素消融；这是本 pilot 的局限，不是结论。
6. **过度预测**（弱，提示）：A 的验证 F1 在 2048 步后因精确率下降而回落；基因后验过滤（M29 已验证对 Carbon-A 偏置式预测有 +1.7 至 +3.3 的增益）可能给 B 同样的收益，尚未测。

## 8. 下一步建议

1. **立项 C1 并扩大**：按 07 号文档的面板计划，在更多训练物种（含时间留出面板的训练侧）上放大 B 配方——先在 ont 上做"B 续训 + 更多物种/唯一窗口"的阶梯实验，目标是把 DEV 推到 70 以上（追平 GENERanno fresh-joint），成本主要是 DP 的 CPU 时间（≈25 s/步，B 的 1,536 步约 10 h；更多层 LoRA、更大 rank 的显存仍在 6 GB 级）。
2. **补三个低成本对照**（均可在 ont 上做）：(a) 同配方 GENERanno 12 kb 窗口 + LoRA（分离"骨干监督"与"窗口/LoRA"）；(b) A 配方用最后一层特征（分离选层）；(c) 基因后验过滤 + 温度校准（M29-A2 的方法）直接作用在 B 的链上。
3. **多 seed 与时间留出评测**：B 配方跑 3 seeds；在 10 号文档的独立植物面板上做零样本评测（NT-v2 排除植物，是"干净来源"的最强论据）。
4. 这条线与部分标签适配（C2）天然兼容：B 的损失本来就是边缘化部分观测似然，可直接在新物种不完整注释上做 LoRA 适配（M30 的主张线），NT-v2 骨干使"没有任何注释监督暴露"的表述成立。

## 9. NT-v2 预训练数据暴露与评估口径的限定

- **NT-v2-500M-multi-species 是纯自监督（掩码语言模型）**，预训练数据为 InstaDeep multi_species_genomes（约 850 个物种的基因组 DNA），**训练目标不含任何基因/CDS 注释，也无注释监督的微调**。公开模型卡与数据集卡声明植物基因组被排除（M21 溯源 scout 的记录，来源 `docs/…/M21-CLEAN-BACKBONE-PROVENANCE-SCOUT`；该声明基于卡片，未独立审计）。所以与 GENERanno/Carbon-A 骨干（注释监督、拟南芥/水稻在其训练快照内）相比，这里的骨干没有见过拟南芥/水稻的序列或注释。
- 但**头与 LoRA 是在拟南芥/水稻的 4 条训练染色体上用注释训练的**，DEV 是这两个物种的另外两条染色体——DEV 对我们仍是同物种开发面板（不是独立物种），且被项目反复使用；与 Helixer（含这两物种）、Carbon-A（训练快照内）的比较不对称。独立物种的结论需要 10 号文档的时间留出面板。
- DEV 评估了两次（A step 2048 与 B step 1536），选择依据均为内部验证；单 seed；无多重比较校正。

## 10. 局限与偏离

- 选层偏离"历史最佳层"，依据是 token 级线性探针（预设规则，§1.2）；未在全管线里做最后一层的消融。
- 训练 A 的 cosine 计划是 4,608 步，但早停在 3,072（选 2,048），lr 并未退火完（step 2048 时 1.9e-4）；B 的 lr 退火完整但步数少。两者都没有在"收敛"处评估。
- A→B 是同一头的顺序训练，B 的头 lr 与 LoRA lr 为预设值，没有扫描；单 seed。
- 内部验证用完整留出染色体 5,894 条参考，但留出的水稻染色体基因数少（1,601），按物种的验证噪声较大。
- 与 Helixer/Tiberius/ANNEVO 只比较了既有 DEV 的 pooled/物种值；没有同函数重算它们的碱基级/背景/分层数据。
- ont 为共享 GPU/CPU（M30、PlantCAD2、TE benchmark 等任务并存），步时与吞吐是共享条件下的数字；训练 A 有 3 次 OOM 重启（最多损失 64 步）。
- 未做基因后验、校准、共形集合；这里的 F1 全是未过滤 MAP 输出。
