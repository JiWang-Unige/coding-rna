## 1. 软件与模型

- 环境 `~/envs/vipsania_m38`（ont）：Python 3.12.12，vipsania 1.1.0，TensorFlow 2.19.1（pip 自带 CUDA 12.5 库），keras 3.15.1，hidten 1.0.0，bricks2marble 0.1.3。版本明细见 `outputs/M38-VIPSANIA/env_versions.json` 与 `env_freeze.txt`。
  - 作者 README 里的类群数字出自 1.0.0；我们用 1.1.0，论文中注明。
- 模型：Streptophyta `j9m0cdmk`，按 ID 固定，不按类群名调用。缓存在 `outputs/M38-VIPSANIA/vipsania_cache/`，sha256 存于 `model_j9m0cdmk.sha256`，运行前校验。

## 3. 运行模式（每个基因组两次）

- **ft（判据模式）**：`vipsania annotate j9m0cdmk genome.fa --finetune`，作者默认参数：10 epoch、lr 1e-4、T 200,000、有效批 64。
- **pre（描述）**：只用预训练模型注释，不微调。
- 只有 24 GB 显存逼出来的改动：
  - `--finetune_B`：空闲显存 ≥ 23,040 MiB 用 2，否则用 1，靠梯度累积保持有效批 64；
  - 注释遇到显存不足时，`-B` 依次降为 4、2、1。
  - 实际取值记入每次运行的 `run.json`。
- 不做任何参数调整，不因结果重跑；只有运行失败才重试。

## 4. 评分

- **区域**：
  - DEV = 拟南芥 `NC_003074.8` + 水稻 `NC_089041.1`（`m29_common.DEV_SCOPE`；与已发表的 70.107、77.41、参考 7,728 条同口径）；
  - B 集 = Dryas `NC_141367.1 / 69 / 71 / 73` + Eschscholzia `NW_028238309.1 / 461.1 / 483.1`。
  - 每种模式各评一次；结果文件已存在时评分器拒绝覆盖。
  - 我在派任务时把 DEV 误写成 `NC_003071.7` + `NC_089044.1`。那两条是 M31 / M34 的内部验证（select）染色体，不在本协议的评分范围内。
- **主指标**：pooled exact-chain F1（CDS ≥ 96 bp 规则，与我方 T2 / T10 / k50 臂同规则），以及精确率、召回、逐区段 F1。另报不加 CDS ≥ 96 规则的 pooled 值，与以往外部工具的已发表行对照。
- **配对比较**：
  - DEV：1 Mb 块配对 bootstrap（`m34_boot_pair.py` 本身；2,000 次，seed 0），对照 T2、T10、k50U、k50F，T2_s2 有则加。
  - B 集：`m34_p2b_score.run_scoring`，对照 T2、T10。
- **评分器验证**（2026-11-04，同一转换器、同一代码路径复算已发表值，逐位一致）：
  - DEV：GENERanno fresh-joint 70.107、Carbon-A 未过滤 75.24、过滤 77.41、k50U 71.631；
  - bootstrap T10 − T2：−0.9646 [−1.5164, −0.2890]；
  - B 集：T10 / T2 = 68.329 / 68.470，差值 −0.141 [−0.531, +0.277]。

## 5. 结果的性质

- DEV 与 B 集上的结果都是**描述性**的。C1 判定只在面板上做（12-01 后，P6 基线同批），判据见报告 28 §6。
- C2 的零注释参照：在 DEV 上把 Vipsania 与 T10（全标签）、k50U、k50F 并列。
  - 注意：k50 两臂只在新物种上砍标签，DEV 物种对两臂都是全标签。所以这只是"零注释工具在全标签物种上能到多少"的描述，不是注释量曲线上的同口径点。
  - 同口径的点要在 8 个新物种的内部验证区段上跑，不在本协议内。

## 6. 算力与停止条件

- 执行顺序：
  1. GPU 小测：拟南芥训练染色体 `NC_003070.9` 的 5,000,001–7,000,000（不评分）；
  2. 512 窗口的微调探针，测出每窗口秒数，算出每个基因组的微调时间上界；
  3. 四个基因组按大小从小到大，各跑 pre 与 ft；
  4. 在 CPU 上评分，写 `DEVB_DONE`。
- 估计：微调每个基因组是固定的 64,000 个 20 kb 窗口；4090 上约 4–6.5 h，四个合计约 12–36 GPU h，中值约 22 h（用户批准时按约 15–20 GPU h 估）。
- **停止条件**：若探针得出的单基因组微调上界超过 6 h（四个合计约 24 h），作业在小测后退出（exit 25），队列直接进入 T2_s3，再由用户决定是否另找时段。任一步失败也不阻塞队列。
- 同卡有他人进程时，作业等到空闲显存 ≥ 11.5 GiB 再开始。
