## 1. PlantCAD2-Small 是否带 MLM 预测头（2026-11-11 在 ont 上核实）

- 检查点 `~/plantcad2_work/models/PlantCAD2-Small-l24-d0768/pytorch_model.bin` 共 413 个张量，其中有 `lm_head.lm_head.weight`（8 × 768）和 `lm_head.complement_map`（8）。
- `lm_head.lm_head.weight` 与输入嵌入 `caduceus.backbone.embeddings.word_embeddings.embedding.weight` **逐元素相等**（最大差 0.0），即权重绑定。
- 头的类是 Caduceus 的 `RCPSLMHead`：
  \[ \text{logits}(h) = h_{[:768]} E^\top + \text{flip}_{\text{通道}}(h_{[768:]})\, E[\text{comp}]^\top \]
  其中 \(h\) 是 `last_hidden_state`（1,536 维 = 正链视图 | 反向互补视图），comp = config 的 complement_map（0,1,2,6,5,4,3,7）。
- 词表：[PAD]=0、[MASK]=1、[UNK]=2、a/c/g/t = 3–6（第 8 位补齐）。
- 报告 16 §2 已用 `AutoModelForMaskedLM` 复核过 MLM 精度（Small 在拟南芥 chr3、8 kb、15% 全换 [MASK] 下 0.545 / 0.563），说明头和代码路径是对的。

**结论**：带 MLM 头，而且不用加载额外权重。我们训练时加载的是 `AutoModel`（Caduceus 骨干），它返回的正是 LM 头的输入；LM 头就是骨干里冻结的输入嵌入。所以 M40 直接复用**预训练好的、冻结的** LM 头（`m40_mlm.lm_logits`），不新建 LM 头，也不需要“只在 LoRA 层上加对比 / 重建目标”这类替代方案。

- 复用原头的好处：MLM 损失一开始就有意义（LoRA 的 B 矩阵初始为 0，第 1 步就是预训练模型本身）。这样辅助项约束的是“LoRA 改动后，编码器仍能解释序列”，而不是先去学一个新头。
- MLM 梯度只到 LoRA：LM 头和嵌入是冻结的，C0 头不在 MLM 的计算路径上。

## 2. 方法

### 2.1 每一步的损失

记第 \(s\) 步（从 0 起）的辅助权重为 \(\lambda(s)\)。一个抽样（draw）的损失是：

\[ \ell_{\text{draw}} = \frac{\text{CRF\_NLL}}{n_{\text{known}}} + \lambda(s)\cdot\frac{\sum_p w_p\,\text{CE}_p}{\sum_p w_p} \]

一步的损失是 batch 内 8 个抽样的 \(\ell_{\text{draw}}\) 之和除以 8（与 M34 相同）。

- **CRF 项**：与 M34 完全相同。部分观测似然，未知位置边缘化（处理 U）；已知位置数 \(n_{\text{known}}\) 的归一化方式不变；用的是同一个 DP 池。
- **MLM 项**：\(p\) 取被选中遮盖、且在作用域内的碱基，每个碱基只计一次。计在拥有该碱基的窗口里（沿用冻结几何的最近中心归属）。CE 是 8 类词表上的交叉熵；\(w_p = 1\)，重复区取 \(10^{-4}\)。
- **λ 的 schedule**（参照 Vipsania“辅助项先 0 后升”）：
  - 前 307 步（10%）\(\lambda = 0\)，此时**不遮盖**，每个抽样走 M34 原代码路径（`m34_backend.window_pots`，输入不加改动）；
  - 第 307–612 步线性升到 \(\lambda_{\max}\)；
  - 第 613 步起保持 \(\lambda_{\max} = 0.1\)。
- **为什么选 \(\lambda_{\max} = 0.1\)**：CRF 项是每个已知碱基的平均 NLL，MLM 项是每个遮盖碱基的加权平均 CE（预训练模型约 1.1 nat），两者同为“每位置平均”，量级相近。0.1 让 CRF 项占主导，MLM 只作正则。没有做调参，也不在训练结果出来后改动。冒烟会记录 CRF 与 MLM 两项各自的 LoRA 梯度范数，只作描述（§9 决定卡 1）。

### 2.2 遮盖（每个新物种抽样，在编码器上下文 [ca, cb) 的基因组坐标上）

- **选择与标签无关**：每个 ACGT 碱基以 5% 的概率被选中（参照 Vipsania 的“最多遮 5%”），随机数是 `default_rng([40, draw 序号])`，续训不改变遮盖。选哪些碱基时不看 CRF 标签。
  - 原因：如果只在未知位点遮盖，[MASK] 的位置本身就告诉模型“这里是未选中基因的位点”，而推理时没有 [MASK]，形成泄漏和训练 / 推理不一致。
  - 不看标签地选，作用域只影响哪些位置计损失，不影响输入。
- **替换方式**：选中的碱基 80% 换 [MASK]、10% 换随机碱基、10% 不变（PlantCAD2 预训练就是这个比例）。在上下文坐标里只替换一次，所以重叠窗口看到的输入一致。
- **两遍前向用同一份遮盖输入**：
  - 一遍是 no-grad 前向，结果给 DP；另一遍是带梯度的前向，用于反传。
  - 两遍都用同一份遮盖后的输入，所以 DP 算出的梯度对实际编码的输入是精确的。
  - MLM 项借用 CRF 本来就要做的带梯度前向（共享前向），基本不增加编码器开销。
- C0 头的 DNA 卷积分支仍看原始碱基，遮盖只作用于编码器输入。这不泄漏 MLM 目标，因为 MLM 损失只来自编码器加 LM 头。
- **作用域**（`mlm_scope = unlabeled`，按任务定义“未标注位置”）：
  - 核心区内 seg 与 region 都是 IGNORE 的位置（U 处理下未选中的合格基因位点）；
  - 核心区外的上下文两翼（CRF 从不监督这些位置）。
- **物种范围**（`mlm_species = new`）：只对 8 个新物种的抽样遮盖并计 MLM。两个老物种在每个臂里都是全标签，保持 M34 原路径，输入不改动。
- **重复区降权**：
  - M34 的新物种 prepared 基因组已被 `m34_prep.py` 全部转成大写，软屏蔽丢了。所以从 md5 校验过的 NCBI 原始 `*_genomic.fna.gz`（RefSeq 软屏蔽）读回小写区段，存成每条训练染色体的区段表（`m40_repeats.py`）。老物种的 `data/m1_screen/*/genome.fa` 仍带软屏蔽。
  - 每条染色体都核对：转大写后的序列与训练器读到的序列 md5 一致。
  - 重复区的 MLM 权重为 \(10^{-4}\)（参照 Vipsania）。

### 2.3 标签比例为 0（臂 M40_k0，处理 X）

- 新物种的抽样没有任何 CRF 标签，seg 与 region 全部是 IGNORE，所以不跑 DP、也不跑 no-grad 前向；唯一的损失是 MLM 项。
- 老物种（拟南芥、水稻）照常全标签，与 M34 每个臂相同；C0 头仍从 M32 runA 热启动。所以 k0 是“目标物种零注释”，不是 Vipsania 那种“全程零注释”。
- 在 \(\lambda = 0\) 的前 307 步，k0 的新物种抽样没有任何损失，只有老物种的抽样在训练。

### 2.4 与 M34 相同的部分

- 编码器：PlantCAD2-Small + M35 LoRA（块 12–23，in/out_proj，r 8，α 16，seed 0）。
- 初始化：C0 头取 M32 runA 选定检查点。
- 优化器分组、学习率（头 1e-4、LoRA 3e-4、cosine 到 1e-5、5% warmup）、梯度裁剪 1.0、batch 8、3,072 步、分块反传（每块 2 个窗口）。
- 检查点格式：存点每 64 步，模型文件每 768 步。
- 推理、打分、选点、DEV 工具：都是 M34 的原脚本（`m34_infer_retry.sh`、`m34_val.py`、`m34_select.py`、M32 `c1_eval.py` / `c1_boot.py`）。M40 的模型文件可以被 M34 推理直接读。

## 5. 预注册判据（在任何 M40 输出之前写定）

所有新物种区段的数，都取各臂按 §4 规则各自选定的检查点。

**S1（主判据：半监督增益）**

在 8 个新物种区段 pooled F1 上，取两个配对差的平均：

\[ \bar\Delta = \tfrac12\big[(\text{k25U+MLM} - \text{k25U}) + (\text{k50U+MLM} - \text{k50U})\big] \]

逐物种也算同样的两差平均。

- **成立**：\(\bar\Delta \ge +1.5\)，且逐物种两差平均在 8 个物种中 ≥ 6 个为正。
- **不成立**：其余情况。若 \(\bar\Delta \le -1.5\) 且 ≥ 6/8 为负，记为“有害”。
- **同时报告**：两个单差各自的点值和逐物种方向（描述）。

**seed 噪声的解释规则**：

- P4 seed 重复（报告 20 §16）会给出 k50U 两个 seed 在新物种区段上的差 \(|\text{k50U}_{s2} - \text{k50U}_{s1}|\)。
- 若这个差 ≥ \(|\bar\Delta|\)，S1 的判定照写，但必须注明“效应小于已观测到的单 seed 波动，单 seed 不足以排除 seed 噪声”。是否补 seed 另卡决定。
- 这条规则只影响解读，不改判定。

**S2（零标签点，描述，不设成立线）**

- 报告 k0 的新物种区段 pooled F1 与逐物种值，并列给出：
  - T2 零样本迁移（同区段 68.84，报告 20 §11）；
  - k25U（66.34）、k50U（67.86）、k50F（64.62）、T10（69.62）。
- 不设成立线，原因：
  - k0 的老物种抽样只占 1/5（T2 是 100%），与 T2 不是同一份监督预算，差值同时混了“少看老物种标签”和“多看新物种无标签”两个因素；
  - 没有“k0 不带 MLM”的同口径对照（要加，见 §9 决定卡 5）。

**S3（无害性，描述）**

- 各配对臂与对照在 Ath/Osa select 上的差、在 DEV 上的配对 bootstrap 差。
- DEV 物种在所有臂里标签都完整，所以 DEV 差反映的是“新物种的辅助目标对整体模型的影响”，不是注释量曲线。

**描述量**

- 训练日志中的 MLM CE、MLM 准确率随步数的变化；CRF 与 MLM 两项 LoRA 梯度范数之比（冒烟）；
- 各停点的新物种区段与 select（中间停点只作描述，P4 已显示中间停点摆动很大）。

## 7. 算力、队列与停止条件

- **本会话不占 ont GPU，也不往 ont 队列里加东西**。GPU 冒烟与三个臂由维护会话在 M39 之后排队。入口是 `experiments/M40-SEMISUP-MLM/scripts/m40_run_all.sh`：冒烟 → k25U+MLM → k50U+MLM → k0。每步可续跑，GPU 空闲 ≥ 6 GB 时最多重试 6 次；冒烟失败则整条队列停止。
- **CPU 准备**：重复区索引与 k0 抽样表已在 ont 上用 CPU 生成（§8）。
- **估算**（依据：k25U 与他人共卡时约 40 s/步，k25U / k50U 整臂约 40 GPU h，报告 20 §15–16）：

  | 项 | 估计 | 依据 |
  |---|---|---|
  | GPU 冒烟 `m40_smoke.sh` | ≈ 1–1.5 h | 26 个训练步 + 300 kb 切片推理 / 打分 |
  | M40_k25U_MLM | ≈ 42–46 GPU h | k25U 约 40 h；MLM 搭在已有的带梯度前向上，额外开销是 LM 头（8 类）和 CRF 全未知抽样的 MLM-only 反传，估 +5–15% |
  | M40_k50U_MLM | ≈ 42–46 GPU h | 同上 |
  | M40_k0 | ≈ 32–40 GPU h | 新物种抽样（约 80%）不跑 no-grad 前向和 DP，只跑一遍带梯度的前向 + 反传 |
  | Vipsania 新物种区段 | < 0.5 GPU h | 64 Mb，只用预训练模式；M38 实测拟南芥 119 Mb 240 s、水稻 386 Mb 606 s（`M38-VIPSANIA/events.jsonl`），估 2–3 min 加载与等待 |
  | 合计 | ≈ 120–135 GPU h（约 5–6 天） | 不含他人占卡等待 |

  冒烟的 `projected_train_hours_3072_steps` 会给出实测步时，届时更新本表。
- **停止条件**：
  - 冒烟失败任一项（λ=0 时与 k25U 前 3 步不一致、续训不连续、第 1 步 MLM 准确率 < 0.40、MLM CE 非有限或 ≥ 5、k0 无 MLM 抽样、infeasible > 16、中位步时 ≥ 150 s）→ 不开训，回报；
  - 训练中 `nonfinite parameter`，或 supervise 连续 4 次无进展 → 该臂停，回报；
  - 判据与超参在训练结果出来后不改。

## 9. 需要用户定的点（决定卡草稿，交维护会话上看板）

**用户决定（2026-11-11，在对话中回复“遵循你的建议，继续推进”）**：五张卡都按推荐项执行，即 λ_max 固定 0.1；臂的顺序为 k25U+MLM → k50U+MLM → k0；MLM 只在未标注位置计损失；M40 三臂之后在新物种区段上跑 Vipsania 只用预训练模式；暂不加 k0 的同口径对照。以下保留原卡文本。

1. **`m40-lambda`（辅助项权重）**
   - why：\(\lambda_{\max}\) 决定 MLM 是“轻正则”还是“主导项”。没有调参依据，事后调参会破坏预注册。
   - options：A 固定 0.1（本协议写定）；B 由冒烟实测的梯度范数比按不看结果的规则定（使 MLM / CRF 的 LoRA 梯度范数中位比 ≈ 0.3，截断到 [0.03, 1]），再开训；C 先在 k25U 上做 0.03 / 0.1 / 0.3 三档短跑（各 768 步）再选。
   - consequences：A 最简单，结果为阴性时不能排除权重选得不好；B 不看任何 F1，仍算预注册，多一步人工改配置；C 每档约 10 GPU h、共约 30 h，且要另立选档规则。
   - recommended：A。
2. **`m40-arm-order`（臂的顺序）**
   - options：A k25U+MLM → k50U+MLM → k0；B k0 先跑。
   - consequences：A 先回答主判据 S1（两个配对臂约 90 GPU h 后即可判）；B 先得到 0% 点，S1 推迟约 1.5 天。
   - recommended：A。
3. **`m40-scope`（MLM 计损失的位置）**
   - options：A 只在未标注位置（未知核心位点 + 上下文两翼；任务定义，本协议写定）；B 新物种抽样的所有位置。
   - consequences：A 与“只用无标签信息”的叙述一致，但在 k50U 下 MLM 主要落在两翼和未选中基因位点；B 信号更多，更接近 Vipsania，但有标签的位置同时受两种监督，叙述变成“额外的自监督正则”。
   - recommended：A。
4. **`m40-vipsania-newsp`（在新物种区段补 Vipsania 外部 0% 点）**
   - options：A M40 三臂之后跑 Vipsania 只用预训练模式（可加目标基因组微调）在 8 个新物种区段上（共 64 Mb）；B 不跑，只用 DEV / set B 数并列。
   - consequences：A 约 2–6 GPU h（微调按物种另计），换来与 k0 / k25U 同区段的外部参照，前提是查清 Vipsania 训练集与这 8 个物种的重叠；B 不花算力，但 S2 只能与 DEV 上的 Vipsania 隔着口径比较。
   - recommended：A（只用预训练模式；微调另议）。
5. **`m40-k0-control`（k0 的同口径对照）**
   - options：A 不加，S2 只作描述；B 加一臂“k0 不带 MLM”（新物种抽样无任何损失，λ 恒 0），约 30 GPU h。
   - consequences：B 能把 k0 的 MLM 效应单独测出来；A 省 30 h，但 S2 的差混着两个因素。
   - recommended：A，S1 成立后再考虑 B。
