## 1. 实现

### 1.1 并行 DP 与分配器修复（`a1_dp.py`）
- 每个窗口的 `coarse_channel_nll`（log Zall − log Zobs，精细标签硬约束、粗通道 ε=0.1、未知边缘化、128 外显子、256 bp 检查点）+ 反向，放入 `multiprocessing`（spawn）常驻进程池；worker 内 monkeypatch `src.m28.full_grammar_boundary_compiled._reverse_messages` 为 M29 的共享分配器版本（`m29_reverse_arena.py`，09 已验证梯度逐位相同）。冻结文件未改。
- worker 初始化时做 numba 预编译，并计算一个 1.2 kb 确定性"金丝雀"DP 的 SHA-256；之后**每个任务后重算**，摘要变化即抛错（硬件/解释器静默损坏的廉价哨兵）。
- 训练循环（`a1_train.py`）：冻结编码器不依赖头权重，故由后台线程**提前编码**后续抽样窗口（BF16，驻留 GPU，队列 16 个窗口）；主线程对每个窗口先 `no_grad` 前向得到头 logits，加固定 offset 后提交 DP；梯度回来后重算头前向并反传（逐窗口，避免 8 窗口激活同时驻留）。无观测（全未知）窗口的损失与梯度严格为 0（冻结管线核验过，并有测试），直接跳过 DP。

### 1.2 固定 offset（`a1_offset.py`、`a1_build_offsets.py`）
与奇偶闸门 `m29_gate_parity.build_logits(…,'A_full')` 完全相同的构造（原生 CDS 头 logit 发射 + 转移 TCN 四条轨 + GC 先验），以 5×L 紧凑形式按链存储（`d`、enter_gene、leave_gene、enter_intron、leave_intron），展开后与闸门实现**逐位相同**（测试）。TRAIN 用保存的 Carbon-A 概率（`M28-CARBON-A-TRAIN-RAW`）与 M29 缓存的转移轨；DEV 用 ont 上 SDPA 重跑的 Carbon-A 概率（G0）并在本机重算转移轨。训练窗口的 offset 直接从整条染色体的 offset 切片，不额外编码。
说明：offset 来自 Carbon-A 的 98 kb 窗原生推理，而残差头特征来自我方 24,576 bp 联合编码；二者权重相同，但不是"同一次前向"。这是 09 §9 已明确采用的做法（不再多一次编码）。

### 1.3 模型与配方
- C0（366,191 参数）seed 0 初始化，**`segmentation` 线性层权重与偏置置零** ⇒ 初始头输出恰为 0（测试），初始模型 ≡ 闸门模型。编码器冻结。
- 训练：与冻结 fresh-joint 同一抽样器（`fresh_schedule`，seed 1，层内均匀有放回，原层序）；前 4,608 个抽样与冻结计划 `training_plan.jsonl` **逐一相同**（启动时断言），其后按同一随机流续抽，共 36,864 个抽样（24 遍 × 1,536）。batch 8，4,608 个优化步（任务字面："4,608 个优化步、batch 8"；相对 fresh-joint 的 4,608 次 batch-1 更新，曝光量为 8 倍），AdamW（lr 峰值 3e-4，wd 0.01，betas .9/.999，eps 1e-8），余弦 3e-4→1e-5，5% 线性 warmup（231 步），梯度裁剪 1.0，每窗口损失 × 1/max(1, 精细+粗观测数)/8。
- 检查点：每 128 步写 `ckpt_latest.pt`（模型、AdamW、步数、torch/numpy RNG、配置、抽样位置；原子替换），每 512 步另存模型。外层 `a1_supervise.sh` 自动从最近检查点重启并写 `interruptions.jsonl`。
- lr 试点（100 步，同抽样，lr 0 / 3e-5 / 1e-4 / 3e-4，常数 lr + 10% warmup）：四者在 100 步内逐窗口 NLL 无可见差别（last-50 平均归一化 NLL 0.01323 / 0.01322 / 0.01302 / 0.01314），无发散；因此按任务规定沿用 3e-4。早先 20 步 smoke（warmup 仅 1 步）显示首个更新之后 NLL 暴增，说明 warmup 是必需的。

## 3. ont 稳定性自检与中断记录

- `dmesg` 可读，无 MCE/OOM/EDAC；但历史上约 30 条用户态 segfault 几乎全部标注 "likely on CPU 0/1 (core 0)"（启动时刻 704,000 s 之后），与 09 的解释器异常时间吻合，**怀疑 core 0（逻辑 CPU 0、1）有间歇故障**（13900K，GPU 为 4090，无 ECC）。
- 压力测试：32 个逻辑 CPU **各自固定一个进程**，4 分钟，解释器密集（dict/set/Counter/闭包）+ numba FP64 + numpy 矩阵乘，每次重复比对 SHA-256：共 41,985 次重复，**0 次摘要不一致、0 次异常**，32 个进程摘要全部相同（`selfcheck_cpu_stress.json`）。另有 8 进程 numba 重复、200 次 GPU 矩阵乘、6 次冻结 FP64 DP（值+梯度）重复：全部 0 不一致（`selfcheck_numba_gpu_dp.json`）。故障未能在负载下复现。
- 缓解：所有任务通过 `taskset` 排除 CPU 0/1 与大部分共享核，仅用 16 个逻辑 CPU（`2,4,6,8,10,12,14,16-24`）；worker 金丝雀；每 128 步检查点；训练日志、推理分片均可恢复。
- **训练期间无自发中断**。唯一一次中断是人为注入：step 128 检查点写出后 `kill -9` 训练主进程，监督脚本 30 s 后从 step 128 恢复（日志 `resumed from_step 128`，step 129–≈145 重算，`training.jsonl` 有 2 条重复记录，分析取最后一条），之后一路完成（`interruptions.jsonl`）。推理（`infer_final`）8 条染色体无中断；后验 16 个任务无重试。未发现静默数据损坏迹象（所有闸门/Carbon-A 对照数字与既有记录逐位一致：Carbon-A 78.172/76.063/77.406/75.241，fresh-joint 70.303/70.107，E 72.958，ANNEVO/Tiberius TRAIN 75.542/72.655）。

### 5.4 过滤的两条路线
(i) **自家基因后验**：A1 能量下的后验**严重饱和**（Carbon-A offset 以 nat 计数千的量级，`log P(g)` 绝大多数恰为 0 或极小的数）；TRAIN 排序质量 AUROC **0.660**、AP 0.806（09 中 E/M 池后验为 0.805/0.910），留一染色体选出的阈值六次都是 log P≈−7.5e-9（即"后验在浮点下不等于 1"），效果 73.483→75.423（+1.94）；DEV 用 TRAIN 阈值 71.839→73.882。事后最优与此相同。结论：offset 能量下的后验不是可用的排序/校准量，**C3（配分函数后验）在该能量下不成立，除非加温度校准**。
(ii) **Carbon-A 置信网络 0.1**（未调参）：A1 TRAIN 76.998（AUROC 0.858 / AP 0.926），DEV 75.459（0.865 / 0.927）；对闸门是 77.979 / 77.127，对 Carbon-A 自身 78.172 / 77.406。

## 6. 失败机理分析

1. **饱和的单向损失。** Carbon-A offset 的能量以逻辑回归 logit（每碱基约 ±14）加转移 log-odds（±200）累加，一条基因的路径分数达数千 nat。因此在 CRF 里：标签链已是 MAP 的窗口 `log Zall = log Zobs`（FP64 精确相等，如 logZ=58611.47，损失与梯度恰为 0）；基因间区的假阳性路径概率 ≈ exp(−数千)，**梯度同样恰为 0**。只有"标签链不是 MAP"的窗口（约 37–42%）提供梯度，且梯度方向只能是"提高标签路径上的角色分数"。对 batch=8 的每个更新，梯度全为"向上"的信号。
2. **学到的是全局偏置。** 最终头 logit（DEV 水稻 5.0–5.5 Mb 区段统计）：背景/内含子角色约 −0.17（|·|≈0.18），外显子编码角色均值 +2.5（标准差仅 ≈1），外显子末碱基/受体后角色 +5.2～+7.0，起始/终止 +3.2/+5.1。TRAIN 全局均值向量见 `results/head_bias_train_mean.npy`（编码角色 ≈+2.25，边界角色 +4.7～+6.3）。这类"所有基因相关角色一起加分"的偏置在训练窗口（基因富集）上降低 NLL，却在整条染色体推理时抬高所有候选基因与外显子，产生更多预测/合并。
3. **没有被惩罚的误报方向。** 因为 (1) 的饱和，训练中没有任何项抑制背景处的编码，更没有"相邻基因不合并"的负例。
4. **劣化与步数同向缓增**（512 步已 −1.55，2560 步 −3.39，终点 −3.02），对 lr 不敏感（试点无差），说明是目标/能量尺度问题，不是优化噪声。
5. 一个粗糙诊断（事后）：从 A1 头里减去 TRAIN 全局均值向量后重解码 DEV，结果坍缩（水稻仅 158 条链，拟南芥 3,825 条），因为该向量把真正基因处的信号也一并扣掉了；不是有效修复，仅说明偏置与信号不可简单分离。未对其评分。

## 7. 决策门判定与下一步

**判定：不通过。** 要求是 TRAIN 与 DEV 的最佳过滤版本都 ≥ 对应 Carbon-A 过滤版且两物种同向；实际 A1 最佳过滤（Carbon-A 置信）为 76.998 / 75.459，对 78.172 / 77.406，水稻方向更差，闸门+置信（77.979 / 77.127）也没有被超过。**不进入独立植物面板和 3 seeds。**

下一步建议（按性价比；均未执行，需要用户决策）：
1. **修正损失尺度再试同一设计（成本最低，约 15 h 墙钟/次，GPU 一小时级以内）**：对 offset 乘温度 τ（例如 0.02–0.1，使 NLL 不饱和，背景处的假阳性与相邻基因合并路径重新有梯度）；或固定 offset 但在训练损失里加入 BCE/逐碱基辅助项；同时对残差头去偏置（role 层无 bias、加零均值约束或 L2 到 0）、降低峰值 lr（1e-4 以下）、限制步数（本实验 512 步就已劣化）。先在 DEV 单条染色体上用 512/1024 步检查点作早停诊断（每次约 25 min GPU）。
2. 残差头 + LoRA（06 路线 (b)），让编码器参与连接精度；仍需 1 的尺度修正，否则同样饱和。
3. 若主张"自家校准后验"（C3），需要温度/等渗校准；offset 能量下未经校准的后验 AUROC 仅 0.66。
4. 增加训练数据（唯一窗口覆盖），但在 1 之前收益不确定。

## 9. 局限与偏离
- 4,608 个优化步按"batch 8 × 4,608 步 = 36,864 窗口抽样"解读；若按"4,608 窗口 = 576 更新"（09 §9 的字面写法），曝光量只有 1/8。鉴于结果为劣化且与步数同向，较少的更新量不太可能反转，但未测。
- 仅单 seed、无重复；试点只有 100 步、四个 lr。
- offset 的 DEV 概率来自 SDPA（比保存的 FlashAttention-2 约 −0.2 点，09 §7）；TRAIN 来自 FA2 保存结果。闸门、A1、Carbon-A 在 DEV 上使用同一份 SDPA 概率，故差值可比。
- DEV 上 Tiberius/ANNEVO 为既有值，未重算；A1 的 R4 仅 TRAIN。
- 自家后验在闸门上未计算（只对 A1），因此"后验饱和是 offset 能量固有的"为推断，闸门后验可作为 §7 第 3 点的对照补做（≈3 h CPU）。
- 压力测试没有复现 core 0 故障；"怀疑 core 0"仅来自 dmesg 位置标注。
