## 0. 定位：一句话故事

**"一个与骨干无关的概率化基因语法层：把任意 DNA 语言模型变成可用不完整注释训练、输出校准基因后验的完整基因注释器。"**

配套的经验结论（描述，不是主张）：同一语法层接上植物预训练骨干（PlantCAD2 + LoRA），只用拟南芥和水稻训练，在时间留出的 set B 两个物种上零样本 68.57 / 68.39（Carbon-A 过滤 73.98 / 73.32）；但在独立面板核心 10 种上中位数为 55.05，低于 Carbon-A 过滤 12.60 点，也低于 Tiberius 与 Vipsania 微调版，只高于 Helixer（报告 31 §6）。差距集中在长基因、多外显子物种（Amborella、Hakea、Akebia）。因此本文不主张零样本精度，零样本结果作为诚实基准与局限报告。

为什么不是"新 SOTA 工具"：

| 事实 | 出处 |
|---|---|
| 同主权重的 Carbon-A（2026-10-08 发布）在 DEV 过滤后 77.41（未过滤 75.24）；我方最佳配方 PlantCAD2 + LoRA（只训拟南芥 + 水稻，T2）DEV 73.88 [71.80, 75.63]，对 Carbon-A 过滤 −3.53 [−4.41, −2.76]（配对）；在冻结 Carbon-A 特征上学残差/适配头没有增益（M29-A1/A2、M30） | 07 §5–6、§9；报告 20 §7 |
| ANNEVO（MoE + Viterbi，566 物种）、Tiberius（可微 HMM，多谱系）、GeneCAD（PlantCAD2 + CRF）、PlantGeneAnn（Mamba-MoE）已占据"GLM/深度表示 + 语法解码"和 MoE 两个点 | 05 §3.1 |
| 单 4090 共享 + Baobab 12-01 前冻结，不可能复制 ANNEVO/Carbon-A 的训练规模 | 00 §3 |

与 Carbon-A/ANNEVO/Tiberius 真正不同、且已有证据的三件事：

1. **未知位置边缘化**（配分函数 CRF 的"部分观测似然"）：填背景会让召回崩溃（M30：U − F = +16.5 / +14.2 点，两物种同向）。这是 Carbon-A/ANNEVO/Helixer 训练目标做不到的。
2. **自带校准的基因后验**：配分函数训练的模型 τ=1 即校准（M33：ECE 0.031，AUROC 0.82），不需要 Carbon-A 那样单独的置信网络（ECE 0.067）；过滤在同物种 +1.7、新物种 +2.3–2.5 点。
3. **骨干无关，且植物预训练骨干下跨物种零样本接近 Carbon-A**：同一头、同一语法、同一数据下已跑通 NT-v2（纯自监督，非植物）、PlantCAD2（纯自监督，植物）、GENERanno/Carbon-A 三种骨干，并给出受控的骨干贡献分解（05 §3.2 第 2 条列为文献空白）。PlantCAD2 + LoRA 只用拟南芥 + 水稻训练，在 set B 两个时间留出、且不在其预训练里的物种上零样本 68.57 / 68.39，比 Carbon-A 过滤版（73.98 / 73.32）低 5.4 / 4.9 点；NT-v2 + LoRA 在同一集合上是 49.92 / 44.09。**[DEV / set B，单 seed；独立面板待测]**

论文主线因此是 **"框架能力 + 多骨干一致收益 + 植物预训练骨干下的跨物种零样本 + 注释效率"**，而不是"零样本精度第一"。精度表仍要做（审稿人必问），但主张写成"在每个发射源上都一致提升，并在独立面板上接近最强工具（Carbon-A）"；"达到"或"追平"只在面板数字支持时才用。

## 2. 论文大纲

### 题目（候选）

1. *A backbone-agnostic probabilistic gene grammar turns DNA language models into calibrated, annotation-efficient gene annotators*
2. *Learning complete gene structures from incomplete annotations with DNA language models*
3. *Calibrated ab initio gene annotation from partial supervision across DNA foundation models*

2026-11-17（C1 面板判定不成立，用户决定 `outline-c1fail-review`）：采用候选 2；候选 3 为备选。

### 摘要骨架（约 150 词，Nature 系无结构摘要）

1. 问题：真核基因注释的深度方法（Helixer、Tiberius、ANNEVO、Carbon-A）都需要大规模完整注释训练，输出单一最长转录本，没有校准的基因级不确定性。
2. 方法：提出 **[软件名，暂 cdsgram]**：完整 CDS 语法下的全集合配分函数 CRF，精细标签硬约束、未知位置边缘化；整条 contig 精确解码；后验直接可用。
3. 结果 1（骨干无关）：同一头、同一语法在 NT-v2、PlantCAD2、GENERanno 上一致；LoRA 的 DEV 增益 NT-v2 +12.7、PlantCAD2 +12.3 点（63.61、72.22，M31 B 与 M35 同条件）**[终版数字待 3 seeds]**。
4. 结果 2（零样本基准，如实报告）：只用拟南芥和水稻训练的 PlantCAD2 + LoRA 在 10 个时间 / 来源留出的植物基因组上，零样本中位 exact-chain F1 55.1，高于 Helixer（42.1），低于 Tiberius（59.3）、Vipsania（57.4）与 Carbon-A（67.7）；差距主要在长基因的多外显子连接上。

### Discussion（要点）

1. 框架层价值与"骨干会变"：今后更强的开放骨干可直接接入（已用三种骨干证明）。
2. 不完整注释训练的适用范围：参考标签只覆盖部分基因时，边缘化未标注位置能避免召回崩溃（M30；P4 +3.24，8/8，单 seed）；但把噪声伪标签（自训练高后验链、蛋白比对链，约四分之一错误）当作部分观测时，边缘化不惩罚未知区段里的多报，适配后精确率下降、整体变差（M36）。可用的不完整监督因此是"正确但不全"的标签，不是"多而带噪"的标签；与 BRAKER 式证据驱动流程的衔接需要另外处理种子噪声（例如对种子做后验或证据一致性过滤后再训练，本文未检验）。
3. 校准后验的用途：注释质控、选择性下游分析、泛基因组比较。
4. 局限（必须写）：独立面板上零样本精度明显低于 Carbon-A（中位数差 12.6 点），也低于 Tiberius 与 Vipsania；失分集中在长基因、多外显子物种。终版只训两个物种，面板只跑了一个 seed（补跑见 Supp.）；DEV 的两个物种在 PlantCAD2 预训练内，DEV 数字不能当作跨物种证据；M34 的 8 个新训练物种中 5 个在 PlantCAD2 预训练里同种或同属；多物种放大在本预算（3,072 步、等权重抽样、单 seed）下无增益，未检验更多步数或更大批；多外显子连接仍是主要误差；仅 CDS（无 UTR、无 ncRNA）；仅最长/主转录本评估的局限；训练面板偏 RefSeq/Gnomon 标签风格；骨干预训练暴露（PlantCAD2 预训练窗口取自注释基因 ±5 kb；GENERanno/Carbon-A 快照含拟南芥/水稻）。
5. 展望：UTR/ncRNA 语法扩展、泛基因组图注释；测试时自适应在本文设置下不成立（M36），若再做需先解决种子噪声与多报（见第 2 点）。

## 4. 对三个问题的判断

### 4.1 GPU 配额

1. 论文设计已经把**训练压到 LoRA + 小头**（PlantCAD2 路径显存峰值 3.8 GB；M35 配方 1,536 步约 21 h，T10 的 3,072 步实测墙钟约 38 h；PlantCAD2 版头的参数量 **[待核]**），昂贵部分是推理与基线。这仍可以写成卖点："在单张消费级 GPU 上一两天内训练"——ANNEVO/Carbon-A 做不到；但不再是"一天内"（那是 NT-v2 路径的数字）。
2. 优先级按"改变结论的概率 / GPU 时"排：P1–P3 决定故事，必须做；P6 基线中 Carbon-A 最贵，可先只跑核心 10 物种（5.1 Gb），两个大基因组放补充。
3. Carbon-A 结果**不需要重复**：CADB 已公开其对 48,167 个装配的注释；若面板物种在 CADB 中，可直接下载其 GFF3（需核对版本与装配一致），省下 72–96 h。**[待核实：CADB 覆盖面板物种与否]**
4. 面板推理用 PlantCAD2 路径实测约 20–36 kbp/s（B 集 273 Mb 用 3.6–3.75 h，DEV 53.4 Mb 约 25 min），与 GENERanno 路径（17 kbp/s）同量级，比 NT-v2 路径（160–200 kbp/s）慢约 5–10 倍；"放弃 GENERanno 骨干能省算力"不再成立，面板推理成为主要 GPU 开销之一（P5）。

### 4.2 "能做的方向都被做了吗"

被占据的（不要做主贡献）：MoE（ANNEVO、PlantGeneAnn）；GLM 微调 + Viterbi/CRF（Carbon-A、GeneCAD、GeneDecoder）；可微 HMM（Tiberius）；基因置信网络（Carbon-A）；大规模注释资源库（CADB、Tiberius 2,948 装配）。

### 4.3 用户提出的三个方向

**泛基因组**：可做，且便宜（只推理）。建议口径不是"泛基因组注释工具"，而是"**不确定性感知的多装配注释一致性**"：同一模型注释水稻 N 个装配，把后验投射到同源位点，区分"后验一致缺失（真 PAV）"、"后验不确定（结构变异/装配问题）"与"注释差异"；用各材料公开 RNA-seq 做计算验证。风险：需要同源位点映射（minimap2/liftoff 级工具即可）；不需要新训练。适合作 Fig. 6(b)。

**改进"最长转录本"默认**：这是本框架相对 Carbon-A/ANNEVO 的真实结构优势（集合后验），成本低。做法：每个位点输出后验 top-k 合法结构；评估改为"命中任一注释 isoform"并报告 isoform 召回；用 RNA-seq 剪接连接验证新 isoform。风险：ab initio 预测 isoform 的上限可能不高，要把主张限定为"后验排序的候选结构召回更多注释 isoform"而不是"预测可变剪接"。适合作 Fig. 6(a) 或 Fig. 5 的一个面板。**两者取一作主应用，另一进补充**；建议先做 (a)（纯 CPU，与 C3 同一套后验），(b) 作第二篇或补充。

**non-coding RNA 注释**：**不建议进入本篇**。理由：(1) 语法完全不同（无 ORF/相位约束，lncRNA 的"结构"主要由表达定义），当前 CDS 语法与 15 角色不能复用；(2) 参考 lncRNA 注释噪声大、物种间不可比，评估标准没有共识，审稿人无法判断"好"；(3) 需要新的监督和新的基线（无 ab initio lncRNA 基线可比）；(4) 算力上是第二个项目。更现实的中间步是 **UTR/完整转录本语法**（Helixer 预测 UTR，Carbon-A/ANNEVO 不预测），可写进展望，或作第二篇的切入点。
